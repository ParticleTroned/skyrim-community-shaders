## COC endurance: 25 transitions with 10-second pacing

On September 13, the same clean main-VR **e4cfd8f2f** test AIO
(Build **2f6432ddbcbd**, PID **38084**) completed **25/25 COCs** with
**25 strict terminal PASS** results. The measured batch took **321.316 s**.
This remains integration-build evidence, separate from PR82 implementation
head **76f9418ab**.

After one unmeasured Windhelm positioning COC, the server alternated
Dragonsreach and Windhelm with a **10 s pause before every measured COC**.
Loading and strict stabilization add to that pause. Each transition had
one strict waiter (30 s maximum); VR FPS Stabilizer owned profile changes.
Dragonsreach selected native DLAA; Windhelm selected DLSS HoshiPa at
0.85 render scale. The runtime fixture remained FOV/TAA 0.3/0.3/0.7.

PR73's published 0.815 / 0.769 s averages measure NVIDIA setting switches
and are not a COC baseline. Local archives do retain two interrupted
25-COC attempts with 5 s pacing on exact PR73 source `554e484e3`, Build
`e7e9fa2d13f2`: `simple-coc-25-5s-20260911T181040Z` and
`coc25x5-20260911T194058Z`. Both verified logs show one recovered
render-target relatch retry during unmeasured Windhelm positioning,
because vendor resources were still in use. Neither logs a retry during
its first measured move to Dragonsreach. Both attempts subsequently
crashed, leaving no complete scenario receipt or matched strict-timing
baseline. These partial observations establish that the Windhelm retry
already occurred on PR73; they cannot establish its frequency across a
complete PR73 COC pass. The current run records one recovered retry on
each of 12 measured Windhelm returns and none on 13 Dragonsreach moves.
