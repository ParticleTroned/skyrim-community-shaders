## Task 11 entry audit

The existing authoring boundary is `CharacterCategoryAuthoring::Update` at
an accepted deferred lighting pass. `NiAVObject::GetUserData()` follows
ancestry to the owning actor. Material classification currently recognizes
face, exposed skin and hair; opaque unselected actor surfaces and the player
are excluded. The attributed `task11-mask-reference` capture preserves this
baseline but does not verify equipment ownership.

CommonLib exposes the actor's current `BipedAnim::objects` item metadata and
`partClone` attachment, separately from `bufferedObjects`, plus `actorRef`.
This is the concrete boundary to qualify for equipped clothing, armour and
weapons. A shared material, generic skinning or mesh name cannot substitute
for a current owned attachment. Any cache must prove equip/drop/lifetime
freshness; rendering must not retain borrowed form/scene pointers. Rigid
and sheathed attachments require explicit inclusion tests and selected
geometry remains the coverage authority when the face is hidden.

Packing is not free: descriptor bits 9-10 encode categories and bit 11 is
the exclusion flag. The texture codec already uses semantic ID 4 for
Excluded, encoded as byte 1; face/skin/hair use bytes 85/170/255. An extension
must update the descriptor producer/consumer and one versioned codebook
together without touching the separate inverse-vertex-AO channel. It must
also update the three-strength mask constant, nine diagnostic counters,
early bounds reduction, all-category iteration, settings/schema/UI and
shader compatibility. Appending Clothing=4 would be incorrect.

The next equipment implementation must preserve existing saved categories,
hair=true/0.65, player exclusion and mono SE/AE support. New category controls
need backward-compatible defaults and explicit shield/sheathed/attachment
policy. Ownership correctness, mask correctness, aesthetics and performance
are separate qualification results. Task 11 remains open.
